# Issue Tracker: Epics and Tickets

Issues for this repository live as Markdown tickets under `docs/epics/`.

## Conventions

- One effort per directory: `docs/epics/<epic-slug>/`.
- Each epic has a `README.md` containing its summary, ticket index, and sequencing.
- Detailed requirements and decisions live in `spec.md`.
- Implementation tickets live at
  `docs/epics/<epic-slug>/tickets/<NNN>-<ticket-slug>.md`.
- Ticket numbers use three digits and are unique within their epic.
- `Status` records implementation progress using `Todo` or `Done`.
- `Triage` separately records one triage role from
  `docs/agents/triage-labels.md`.
- Dependencies and the relevant spec section are recorded near the top of each
  ticket.
- Tickets describe observable acceptance criteria and implementation tasks.

## When a skill says “publish to the issue tracker”

Create or update the appropriate epic under `docs/epics/`. Add one Markdown file
per implementation ticket and update the epic’s `README.md` ticket index and
sequencing.

Do not create GitHub issues or files under `.scratch/` unless the user explicitly
requests a different workflow.

## When a skill says “fetch the relevant ticket”

Read the referenced ticket path. A shorthand reference such as
`agent-native-evidence-uploads/003` resolves within that epic’s `tickets/`
directory.

Read the epic’s `README.md` and relevant `spec.md` section for surrounding
context.

## Triage notes and agent briefs

Record triage notes or an agent brief in the ticket itself under an appropriately
named heading. Any text generated by the triage skill must begin with:

> *This was generated by AI during triage.*
